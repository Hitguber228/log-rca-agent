# SRE Log RCA Agent & Observability Platform

Комплексная автономная SRE-платформа мониторинга, сбора распределённых логов, автоматического анализа первопричин аварий (Root Cause Analysis, RCA) с использованием нейросетевых моделей (LLM) и доставки сжатых инженерных оповещений в Telegram.

Платформа развёрнута для наблюдения за микросервисной экосистемой сервиса голосовой транскрибации и суммаризации текста (**Audio-Scriber Bot**), фиксирует каскадные падения сервисов, выявляет эпицентры сбоев по сквозным `trace_id` и предлагает регламентные действия по восстановлению (Runbook Actions).

---

## 1. Архитектурный стек и технологии

* **Язык разработки:** Python 3.10+
* **Бэкенд и API:** FastAPI, Uvicorn, Pydantic v2, Jinja2 Templates[cite: 4]
* **База данных и ORM:** SQLite, SQLAlchemy 2.x[cite: 4]
* **Асинхронные интерфейсы и боты:**
  * **SRE Incident Bot:** `aiogram 3.x`, `aiohttp`[cite: 1]
  * **Audio-Scriber Bot:** `python-telegram-bot`
* **ML / Speech-to-Text / LLM:** Faster-Whisper, Groq API (LLaMA / Mixtral), Rule-Based Fallback Engine
* **Анализ логов:** Regex-парсеры, нормализаторы запросов, Tail-f воркеры[cite: 2, 4]

---

## 2. Сквозной пайплайн взаимодействия (Data Flow)

В системе задействованы два независимых Telegram-бота и две серверные подсистемы:

1. **Audio-Scriber Bot (`main.py`):**
   * Пользователь отправляет голосовые или аудиосообщения.
   * Бот пропускает звук через локальный движок `faster-whisper`, формирует транскрипт и отправляет запрос в LLM через `Groq API` для создания выжимки.
   * При возникновении сбоев (или при вызове тестовой аварии `/test_crash`) бот пишет каскадные структурированные логи ошибок с единым `trace_id` в файл `live_service.log`[cite: 1, 2].
2. **Фоновый сборщик логов (`src/watcher.py`):**
   * Непрерывно в режиме реального времени слушает файл `live_service.log`[cite: 2].
   * При появлении записей уровней `ERROR` или `CRITICAL` парсит их и сразу передаёт в FastAPI через эндпоинт `/api/v1/ingest` для сохранения в базе данных SQLite[cite: 2, 4].
   * В течение дебаунс-окна (1.5 сек) группирует связанные ошибки по `trace_id` в единый пакет инцидента.
3. **RCA-Агент (`src/agent.py`):**
   * Анализирует цепочку каскадного сбоя, формирует отчёт о первопричине (Root Cause Analysis) и формулирует план действий по устранению.
4. **Оповещения (`src/notifier.py`):**
   * Форматирует сухой технический алерт без визуального шума[cite: 3].
   * Отправляет сообщение в Telegram авторизованному дежурному инженеру[cite: 3].
5. **SRE Telegram Bot (`bot.py`):**
   * Позволяет дежурному инженеру авторизоваться по 4-значному PIN-коду, просматривать текущий статус мониторинга и последние аварии, а также закрывать инциденты[cite: 1].
6. **Веб-панель управления (`api.py`):**
   * Отображает дашборд, живую ленту логов с фильтрами, интерактивный умный граф каскада сбоев (Blast Radius DAG), глубокий инспектор узлов с регламентными действиями и статус привязки дежурного инженера[cite: 4].

## 3. Подробное описание модулей, классов и функций

### `api.py` — Центральный API-сервер и Web-интерфейс
Координирует веб-интерфейс, предоставляет REST API для сохранения логов, авторизации дежурного и работы с инцидентами[cite: 4].

* **Глобальные переменные:**
  * `PENDING_PINS`: словарь временных 4-значных кодов подтверждения для 2FA-привязки Telegram чата[cite: 3, 4].
  * `CACHE_REPORTS`: кэш сгенерированных отчётов RCA по `incident_id`[cite: 1, 4].
  * `RESOLVED_INCIDENTS`: множество идентификаторов решённых инцидентов[cite: 1, 4].
* **Pydantic-схемы:**
  * `PinRequestSchema`, `BotTokenSchema`, `LogSourceSchema`: валидация параметров авторизации и путей к файлам[cite: 4].
  * `ResolveIncidentSchema`, `ClearCacheSchema`, `RcaRequestSchema`: управление жизненным циклом карточек инцидентов[cite: 4].
  * `IngestLogSchema`: валидация входных логов, присылаемых воркером через HTTP[cite: 4].
* **Ключевые функции и эндпоинты:**
  * `save_token_to_env(token: str)`: обновляет токен бота дежурного в `.env` и в текущем окружении[cite: 4].
  * `get_bot_info(token: str)`: асинхронный запрос к Telegram API `getMe` для валидации токена[cite: 4].
  * `GET /` (`serve_index`): рендерит главную панель управления `index.html`[cite: 4].
  * `GET /api/auth/status`: возвращает статус привязки Telegram, имя бота и активные пин-коды[cite: 4].
  * `POST /api/auth/request-pin`: генерирует 4-значный пин-код и привязывает его к `chat_id`[cite: 4].
  * `POST /api/auth/unbind`: сбрасывает авторизацию текущего дежурного[cite: 4].
  * `GET /api/settings/log-source` / `POST /api/settings/log-source`: получение и динамическая смена пути к отслеживаемому файлу логов[cite: 4].
  * `GET /rca/incidents`: агрегирует логи уровней `ERROR`/`CRITICAL` из базы данных, выстраивает хронологическую цепочку каскадного сбоя от эпицентра (Root Cause) к последствиям для интерактивного умного графа (Blast Radius DAG)[cite: 4].
  * `POST /rca/analyze`: запускает генерацию RCA-отчёта через нейросеть с поддержкой кэширования[cite: 4].
  * `GET /api/logs/search` и `_execute_log_search`: фильтрация, поиск по ключевым словам/регулярным выражениям и постраничная пагинация логов в SQLite[cite: 4].
  * `POST /api/v1/ingest`: сохраняет единичный лог в базу данных SQLite (`LogEvent`)[cite: 4].

### `bot.py` — Telegram-бот дежурного инженера SRE
Обеспечивает мобильное рабочее место для дежурного SRE-инженера на базе фреймворка `aiogram 3.x`[cite: 1].

* **Функции генерации интерфейса:**
  * `get_incident_action_keyboard(incident_id, is_resolved)`: формирует inline-клавиатуру под алертом с кнопками смены статуса (Resolved/Reopen), сброса кэша и быстрой ссылки на дашборд[cite: 1].
* **Хэндлеры команд:**
  * `@dp.message(CommandStart())`: обработка `/start`, отображение текущего `chat_id` и инструкций по привязке через PIN-код[cite: 1].
  * `@dp.message(Command("status"))`: проверка текущего дежурного, состояния привязки и доступности отслеживаемого файла логов[cite: 1].
  * `@dp.message(Command("incidents"))`: вывод 5 последних критических аварий прямо в чат Telegram[cite: 1].
  * `@dp.message(Command("unbind"))`: сброс привязки текущего дежурного чата[cite: 1].
  * `@dp.message(F.text)` (`handle_pin_verification`): перехват 4-значного PIN-кода и валидация через функцию `verify_telegram_binding`[cite: 1].
* **Callback-хэндлеры:**
  * `handle_resolve_callback` / `handle_reopen_callback`: переключение статуса решения аварии[cite: 1].
  * `handle_clearcache_callback`: очистка кэшированного RCA-отчёта для принудительного повторного анализа[cite: 1].
* **Точка входа `main()`:**
  * Сбрасывает старые вебхуки (`drop_pending_updates=True`) для избежания конфликтов и запускает polling в сессии `aiohttp`[cite: 1].

### `src/watcher.py` — Детектор аномалий и сборщик каскадов
Фоновый сервис, отслеживающий появление новых строк в файле логов[cite: 2].

* **Функции:**
  * `send_event_to_api(ev: Dict[str, Any])`: отправляет структурированное событие через HTTP POST на `/api/v1/ingest` FastAPI-сервера, гарантируя сохранение в БД.
  * `run_watcher()`: основной цикл мониторинга:
    * Отслеживает изменения пути к файлу через `get_watched_log_path()` и безопасно переоткрывает дескриптор при смене источника[cite: 2].
    * Читает новые строки (`readline`) с конца файла (эмуляция `tail -f`)[cite: 2].
    * Парсит входящие строки через `parse_raw_log`[cite: 2].
    * При фиксации уровней `ERROR` или `CRITICAL` мгновенно пушит событие в API и складывает его в локальный буфер `buffer_errors`[cite: 2].
    * Реализует механизм дебаунса (1.5 сек): если поток каскадных ошибок прекратился, упаковывает накопленный буфер в структуру инцидента, запускает LLM-анализ `generate_rca_summary` и вызывает отправку алерта через `send_telegram_alert`[cite: 2]. Очищает буфер для следующей аварии[cite: 2].

---

### `src/notifier.py` — Форматирование и транспорт уведомлений
Отвечает за сохранение настроек авторизации дежурного и непосредственную отправку сообщений в Telegram[cite: 3].

* **Функции работы с конфигурацией:**
  * `get_active_chat_id()`: извлекает актуальный Chat ID из файла `.env` или переменных окружения[cite: 3].
  * `save_chat_id_to_env(chat_id)`: сохраняет новый Chat ID в `.env`[cite: 3].
  * `clear_chat_id_from_env()`: очищает значение Chat ID в `.env` при отвязке[cite: 3].
  * `get_watched_log_path()` / `save_watched_log_path(new_path)`: чтение и перезапись пути к отслеживаемому файлу логов[cite: 3].
  * `verify_telegram_binding(chat_id, pin)`: проверяет совпадение введённого в Telegram 4-значного PIN-кода со сгенерированным в веб-панели и сохраняет привязку[cite: 3].
* **Форматирование и доставка:**
  * `format_incident_alert(incident: Dict[str, Any], rca_summary: str)`: формирует лаконичный, технический алерт без визуального шума[cite: 3]:
    * Очищает цепочку каскада от дублирующихся узлов и системных меток (`system`).
    * Извлекает суть ошибки (Root Cause) без мусорных префиксов.
    * Подставляет автоматические регламентные действия (Runbook Action) на основе характера сбоя (CUDA OOM, Timeout и т.д.).
  * `send_telegram_alert(incident, rca_summary)`: отправляет сформированный алерт через HTTP-метод Telegram Bot API `sendMessage`[cite: 3].

---

### `src/agent.py` — Аналитический движок Root Cause Analysis (RCA)
Отвечает за глубокий разбор инцидента с помощью нейросетевых моделей.

* **Логика работы:**
  * Подключается к Groq API (модели LLaMA-3 / Mixtral).
  * `generate_rca_summary(incident_data: Dict[str, Any])`: принимает полную цепочку каскадного сбоя, формирует системный промпт с контекстом микросервисов и генерирует краткий структурированный отчёт[cite: 2]:
    1. Эпицентр сбоя.
    2. Механизм каскадного распространения ошибки.
    3. Конкретные шаги инженера по устранению сбоя.
  * В случае недоступности внешнего API или отсутствия ключей автоматически переключается на встроенный детерминированный движок (Rule-Based Engine), который строит заключение по эвристическим правилам сигнатур ошибок[cite: 4].

---

### `src/db.py` и `src/models.py` — Хранилище данных
Обеспечивают схему хранения и доступ к событиям через SQLAlchemy[cite: 4].

* **Класс `LogEvent` (`models.py`):**
  * `event_id` (Integer, Primary Key): уникальный инкрементный идентификатор[cite: 4].
  * `timestamp` (DateTime): точное время фиксации лога[cite: 4].
  * `service_name` (String): имя микросервиса (`whisper`, `groq-llm`, `audio-scriber` и др.)[cite: 4].
  * `log_level` (String): уровень логирования (`INFO`, `WARNING`, `ERROR`, `CRITICAL`)[cite: 4].
  * `trace_id` (String): сквозной идентификатор цепочки вызовов[cite: 4].
  * `raw_message` (Text): оригинальный текст сообщения или стектрейс ошибки[cite: 4].
  * `user_id`, `client_ip`: метаданные источника запроса[cite: 4].
* **Подключение (`db.py`):**
  * Инициализирует SQLite движок (`sqlite:///./logs.db`) и фабрику сессий `SessionLocal`[cite: 4].

---

### `src/parser.py` — Синтаксический разбор логов
Преобразует неструктурированные текстовые строки лог-файла в валидные словари Python[cite: 2].

* **`parse_raw_log(raw_line: str)`:**
  * Поддерживает как стандартный структурированный JSON-формат логов, так и текстовые форматы классического вида:
    `2026-10-06 10:14:29 [CRITICAL] [service:whisper] [trace_id:crash-1e8189] Error message`[cite: 1, 2]
  * Извлекает таймстемп, уровень, сервис, сквозной трейс и полезную нагрузку[cite: 2].

---

### `main.py` — Целевой сервис (Audio-Scriber Bot)
Сервис расшифровки аудиосообщений и генерации саммари, выступающий целевым объектом мониторинга.

* **Функционал:**
  * Принимает голосовые сообщения в Telegram, загружает локальную модель `faster-whisper` и распознаёт речь.
  * Отправляет распознанный текст в Groq API для подготовки краткого содержания.
  * Ведёт подробный лог работы в файл `live_service.log`.
* **Эмуляция аварий (`/test_crash`):**
  * Специальная команда для SRE-тестирования[cite: 1].
  * Генерирует уникальный `trace_id` (например, `crash-1e8189a4`) и симулирует реальный каскадный сбой[cite: 1]:
    1. `CRITICAL: whisper_model.transcribe aborted: CUDA out of memory / thread allocation failed`
    2. `ERROR: analyze_with_llm: upstream Groq LLM API connection timeout after 10.0s`
    3. `ERROR: process_audio_analysis aborted ungracefully, failed to deliver result to user`

## 4. Инструкция по установке и запуску

### Подготовка окружения
```bash
python -m venv .venv
# Для Windows:
.venv\Scripts\activate
# Для Linux/macOS:
source .venv/bin/activate
```

Установите необходимые зависимости:
```bash
pip install -r requirements.txt
```

### Конфигурация (`.env`)
Создайте файл `.env` в корне проекта со следующими параметрами:
```env
# Токен SRE-бота уведомлений (получен у @BotFather)
TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz

# Токен бота транскрибации Audio-Scriber (получен у @BotFather)
AUDIO_BOT_TOKEN=0987654321:ZYXwvuTSRqpoNMLkjihGFEDcba

# Ключ к Groq API (для генерации RCA и транскрибаций)
GROQ_API_KEY=gsk_your_groq_api_key_here

# Путь к отслеживаемому лог-файлу
WATCH_LOG_PATH=live_service.log
```

### Запуск компонентов платформы

Запустите 4 независимых процесса в отдельных терминалах:

#### Терминал 1: Веб-панель и REST API
```bash
uvicorn api:app --reload --port 8000
```
Панель управления доступна по адресу: http://127.0.0.1:8000

#### Терминал 2: Фоновый сборщик логов (Watcher)
```bash
python -m src.watcher
```
В консоли появится подтверждение: `🔄 [WATCHER] Мониторинг переключен на файл: .../live_service.log`[cite: 2].

#### Терминал 3: Бот дежурного инженера (SRE Alert Bot)
```bash
python bot.py
```
В консоли появится подтверждение: `🚀 [BOT] Telegram-бот дежурного успешно запущен...`[cite: 1].

#### Терминал 4: Сервис транскрибации (Audio-Scriber Bot)
```bash
python main.py
```

## 5. Проверка работоспособности (End-to-End Test)

1. **Привязка дежурного:**
   * Откройте Telegram и напишите `/start` боту дежурного инженера (`bot.py`)[cite: 1]. Скопируйте ваш `Chat ID`[cite: 1].
   * Перейдите в веб-панель на http://127.0.0.1:8000, вставьте `Chat ID` и нажмите кнопку генерации PIN-кода.
   * Отправьте полученный 4-значный PIN-код в ответ боту дежурного[cite: 1]. Статус в панели сменится на **BOUND**.
2. **Симуляция каскадной аварии:**
   * Откройте Telegram-чат с **Audio-Scriber Bot** (`main.py`) и отправьте команду `/test_crash`[cite: 1].
3. **Результат:**
   * `main.py` запишет каскад ошибок в `live_service.log`.
   * `watcher.py` перехватит события, отправит их в SQLite через API и сгруппирует в инцидент[cite: 2].
   * В Telegram дежурному мгновенно поступит лаконичное оповещение следующего формата:
     ```text
     [CRITICAL] SRE INCIDENT #1791271170
     Time: 10:14:29 | Service: whisper | Trace: crash-1e8189a4

     Root Cause:
     CUDA out of memory / thread allocation failed

     Cascade:
     whisper -> groq-llm -> audio-scriber

     Action:
     Освободить VRAM / проверить лимиты воркера.

     Dashboard: [http://127.0.0.1:8000](http://127.0.0.1:8000)
     ```
   * В веб-панели на вкладке **«Инциденты (RCA)»** появится интерактивная карточка сбоя с полной трассировкой вызовов.
